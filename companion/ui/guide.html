Overview

ScriptBridge is a Tampermonkey-style userscript manager with a unique twist: alongside traditional browser JavaScript injection, it can execute external scripts (Python, Rust, C, CMD, PowerShell) on your local machine. The browser extension and local companion server work as a duo.

Two components:

1. Companion Server (ScriptBridge.exe) — manages scripts, runs external code, serves this dashboard

2. Browser Extension (Chrome MV3) — injects JS into pages, provides popup, talks to companion

Installation

Step 1: Start the Companion Server

Double-click ScriptBridge.exe. The dashboard does not open automatically. For isolated development only, open http://localhost:9876 manually. The server runs in the background with no console window.

Startup: Do not enable automatic startup while the release security issues remain open.

Step 2: Install the Browser Extension

  1. Open Chrome and navigate to chrome://extensions
  2. Enable Developer mode (toggle in top-right corner)
  3. Click Load unpacked
  4. Select the extension/ folder from the ScriptBridge directory
  5. Pin the ScriptBridge icon in your toolbar

Step 3: Verify Connection

Click the extension icon. The status dot should be green, indicating the companion is reachable.

Quick Start

Your First Browser Script

  1. Click + New Script on the dashboard
  2. Set Language to JavaScript and Category to Browser (injected)
  3. Enter a URL pattern like *://example.com/*
  4. Write your code: 
    // Adds a banner to example.com
const banner = document.createElement('div');
banner.textContent = 'ScriptBridge is working!';
banner.style.cssText = 'position:fixed;top:0;left:0;right:0;padding:8px;background:#6c8cff;color:#fff;text-align:center;z-index:99999;font-size:14px;';
document.body.appendChild(banner);
  5. Click Save, then visit example.com

Your First External Script

  1. Click + New Script
  2. Set Language to Python and Category to External (local)
  3. Write your code: 
    import os
import datetime

print(f"Hello from ScriptBridge!")
print(f"User: {os.getenv('USERNAME')}")
print(f"Time: {datetime.datetime.now()}")
print(f"CWD:  {os.getcwd()}")
  4. Click Save, then click the Run button on the script card
  5. See stdout/stderr output in the Run Output modal

Creating Browser Scripts

Browser scripts are JavaScript that gets injected into web pages matching your URL patterns. They work just like Tampermonkey userscripts.

Script Structure

// Basic structure (no metadata block needed, patterns are set in the UI)
'use strict';

// DOM manipulation
document.querySelector('.annoying-popup')?.remove();

// Page modification
const style = document.createElement('style');
style.textContent = '.ads { display: none !important; }';
document.head.appendChild(style);

// Event listeners
window.addEventListener('load', () => {
    console.log('Page fully loaded, ScriptBridge active');
});

Execution Context

By default, scripts run in the MAIN world, meaning they have full access to the page's JavaScript context (variables, functions, etc). This is equivalent to Tampermonkey's @grant none mode.

Security note: MAIN world scripts can be detected by the page. Use ISOLATED world (Settings > Security > Sandbox Mode) if you need stealth.

URL Match Patterns

Patterns determine which pages your script runs on. Supports glob syntax:

PatternMatches
*://*.google.com/*All Google pages (http and https)
https://github.com/*GitHub (https only)
*://*/settings*Any settings page on any domain
*://*/*All pages (use sparingly)

Tip: You can add multiple patterns (one per line) to match several sites with one script.

Userscript API

ScriptBridge provides utility functions available in browser scripts:

// Storage (persists across page loads)
await ScriptBridge.storage.get('myKey');
await ScriptBridge.storage.set('myKey', {count: 42});

// Trigger an external script from the browser
await ScriptBridge.runExternal('script-id-here');

// Notify the user
ScriptBridge.notify('Download complete!', {duration: 3000});

// Cross-origin fetch (bypasses CORS)
const data = await ScriptBridge.fetch('https://api.example.com/data');

// Get info about the current script
console.log(ScriptBridge.info.name, ScriptBridge.info.version);

Execution Model

When you run an external script, the companion:

  1. Writes your code to a temp file in the scripts directory
  2. For compiled languages (Rust, C): compiles first, aborts if compilation fails
  3. Executes the script/binary as a child process
  4. Captures stdout, stderr, exit code, and timing
  5. Returns the result to the dashboard/extension

Timeout: Scripts are killed after the configured timeout (default: 30s). Set to 0 for no limit. Configure in Settings > External Scripts > Execution Timeout.

Compilation Errors

For Rust and C scripts, if compilation fails, you'll see the compiler output (errors, warnings) in the stderr panel. The script won't execute.

Environment

External scripts run with:

  • Working directory: scripts storage dir (configurable)
  • Inherited system PATH and environment
  • Additional env vars from Settings > External Scripts > Environment Variables
  • No interactive input (stdin is closed)

The Duo Pattern

The core innovation of ScriptBridge: browser scripts observe, local scripts act.

A browser script detects something on a page (a download link, a status change, data) and triggers a local script to do something your browser can't: move files, run CLI tools, interact with hardware, call local APIs, automate desktop apps.

Flow

Browser (JS userscript)           Extension           Companion (local)
        |                              |                      |
   Detects event  ──────────────►  Receives msg  ──────►  Runs script
        |                              |                      |
        |                              |                 Python/Rust/PS1
        |                              |                      |
        ◄───────────────────────  Returns result  ◄─────  stdout/exit
        |                              |                      |
   Updates page                        |                      |

Duo Examples

Example 1: Auto-download and organize files

// BROWSER SCRIPT (JavaScript) - runs on a file hosting site
// Detects download links and sends them to a local organizer

document.querySelectorAll('a.download-link').forEach(link => {
    link.addEventListener('click', async (e) => {
        const filename = link.textContent;
        const url = link.href;
        // Tell companion to organize after download
        await ScriptBridge.runExternal('file-organizer', {
            filename, url, category: 'documents'
        });
    });
});
# EXTERNAL SCRIPT (Python) - file-organizer
# Moves downloaded files to categorized folders
import os, sys, json, shutil, time
from pathlib import Path

downloads = Path.home() / 'Downloads'
categories = {
    'documents': ['pdf', 'docx', 'xlsx', 'pptx', 'txt'],
    'images': ['jpg', 'png', 'gif', 'webp', 'svg'],
    'code': ['py', 'rs', 'js', 'c', 'cpp', 'h'],
}

# Wait for download to appear
time.sleep(5)
for f in sorted(downloads.iterdir(), key=os.path.getmtime, reverse=True)[:5]:
    ext = f.suffix.lstrip('.').lower()
    for cat, exts in categories.items():
        if ext in exts:
            dest = downloads / cat
            dest.mkdir(exist_ok=True)
            shutil.move(str(f), str(dest / f.name))
            print(f'Moved {f.name} -> {cat}/')
            break

Example 2: PLC data logger

// BROWSER SCRIPT - runs on your SCADA/HMI web interface
// When alarm fires, trigger local data capture

const observer = new MutationObserver(mutations => {
    for (const m of mutations) {
        if (m.target.classList.contains('alarm-active')) {
            ScriptBridge.runExternal('plc-snapshot');
        }
    }
});
observer.observe(document.querySelector('.alarm-panel'), {
    attributes: true, subtree: true
});
# EXTERNAL SCRIPT (Python) - plc-snapshot
# Captures PLC tag data on alarm event
from pylogix import PLC
from datetime import datetime
import json

# Documentation-only addresses. Never run against plant equipment without authorization.
plcs = {
    'Controller-A': '192.0.2.10',
    'Controller-B': '192.0.2.11',
}

snapshot = {'timestamp': datetime.now().isoformat(), 'tags': {}}
for name, ip in plcs.items():
    with PLC(ip) as plc:
        result = plc.Read(['Program:MainProgram.AlarmCode',
                          'Program:MainProgram.ConveyorSpeed'])
        snapshot['tags'][name] = {t.TagName: t.Value for t in result}

outfile = f'snapshots/alarm_{datetime.now():%Y%m%d_%H%M%S}.json'
with open(outfile, 'w') as f:
    json.dump(snapshot, f, indent=2)
print(f'Snapshot saved: {outfile}')

document.addEventListener('keydown', async (e) => {

        const text = window.getSelection().toString();

Messaging Between Scripts

Browser scripts communicate with external scripts through the extension and companion API:

// From browser script:
const result = await ScriptBridge.runExternal('my-script-id', {
    // Optional data passed as environment variables (SB_* prefix)
    key: 'value',
    another: 'data'
});
console.log(result.stdout);  // What the external script printed
console.log(result.exitCode); // 0 = success

Data passed to external scripts appears as environment variables with the SB_ prefix:

# In Python:
import os
key = os.environ.get('SB_KEY')      # 'value'
another = os.environ.get('SB_ANOTHER')  # 'data'

# In PowerShell:
 = :SB_KEY
 = :SB_ANOTHER

# In CMD:
echo %SB_KEY%

Troubleshooting

Companion won't start

  • Check if port 9876 is in use: netstat -ano | findstr 9876
  • Another instance may be running. Kill it or change the port in settings.
  • Windows Firewall may be blocking it. Allow "ScriptBridge" through.

Extension shows "Companion offline"

  • Make sure ScriptBridge.exe is running
  • Click "Sync Scripts" in the extension popup
  • Check that Settings > Security > Allowed Origins includes chrome-extension://*

Browser scripts not injecting

  • Verify the script is enabled (green toggle)
  • Check URL patterns match the target page
  • Open DevTools console for injection errors
  • Some sites have strict CSP; try Settings > Security > CSP Modification: Always
  • Reload the page after creating/editing a script

External script fails to compile (Rust/C)

  • Ensure rustc / gcc is on your PATH
  • Check the stderr output for compiler errors
  • Set custom paths in Settings > External Scripts

Python script can't find modules

  • ScriptBridge uses your system Python. Install packages with pip install
  • Set a specific Python path in Settings > External Scripts > Python Path (e.g. a venv)

Permission denied errors

  • External scripts run as your user by default
  • Enable "Run as Admin" in Settings > External Scripts for elevated scripts (triggers UAC)
  • Script storage directory must be writable

Need more help? Check the companion server logs (set Logging Level to Debug in Settings > General) or open browser DevTools to see extension messages.
